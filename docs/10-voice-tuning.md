# Настройка голоса и интонации

Практическое руководство: как менять параметры голоса, подбирать голос под
задачу и проверять результат. Все цифры — замеры на BPI-W3, не пересказ
документации Silero.

Инструмент для подбора — `tools/voice_lab.py`. Он синтезирует набор вариантов
на одном тексте, выравнивает громкость, сохраняет OGG для прослушивания и
пишет `manifest.json` с метриками.

---

## 1. Что вообще можно менять

### Уровни настройки — снизу вверх

```
текст  ->  нормализация  ->  ударения  ->  голос  ->  SSML-профиль  ->  синтез
           (цифры,          (silero-      (baya,    (темп, тон,
            латиница)        stress)       xenia…)   паузы)
```

Каждый уровень решает свою задачу, и путать их нельзя: нормализация
обеспечивает **смысл**, ударения — **правильность**, профиль — **характер**.
Ошибка в нижнем уровне не лечится верхним: никакой `pitch="high"` не вернёт
цифру, которую модель вырезала.

### Голоса: 5 встроенных, добавить свои нельзя

| Голос | Характер |
|---|---|
| `aidar` | мужской, ровный, нейтральный |
| **`baya`** | **женский, тёплый, ниже тесситура — выбран основным** |
| `kseniya` | женский, середина, чёткая дикция |
| `eugene` | мужской, ниже тоном |
| `xenia` | женский, выше, легче |

Женские: `baya`, `kseniya`, `xenia`. **Кастомные голоса в Silero v5_5_ru
добавить невозможно** — это фиксированный набор в весах модели. Обучение
своего голоса — отдельный проект, не настройка.

Сравнить голоса на одном тексте, честно по громкости:

```bash
python3 tools/voice_lab.py compare -t "Добрый вечер! Чем могу помочь?"
# -> ./lab/compare/<голос>-cmp.ogg  +  manifest.json с F0 по каждому
```

Громкость выравнивается по RMS обязательно: без этого выигрывает тот, кто
просто громче, а не тот, кто лучше звучит.

### SSML: что поддержано, а что нет

Модель сама парсит SSML, и белый список тегов узкий:

**Работает:**
- `<prosody rate="...">` — темп
- `<prosody pitch="...">` — тон (имя, число или **проценты со знаком**:
  `pitch="+5%"`, `pitch="-10%"`)
- `<break time="400ms"/>` — пауза; можно в секундах (`time="2s"`), всё что
  больше 5000 мс обрезается до 5 с
- `<s>`, `<p>` — границы фраз и абзацев (добавляют паузы)

**Не работает** (падает с `ValueError: not enough values to unpack`):
- `<emphasis>` — акцента на слове через SSML **нет**
- `<say-as>`, `<sub>`, `<voice>`

Это расходится с вики Silero, где теги перечислены как поддерживаемые.
Проверяй по факту, а не по документации.

### Параметры `apply_tts`

В сигнатуре есть параметры акцентуации — они **работают** и по умолчанию `True`:

| Параметр | Проверенный эффект |
|---|---|
| `put_accent=False` | −212 мс длительности, другой звук |
| `put_stress_homo=False` | −288 мс |
| `stress_single_vowel=False` | −125 мс |
| `put_yo=False` | другая фонетика (ещё/еще) |
| `put_yo_homo=False` | −12 мс |
| все сразу `False` | −538 мс |

**`intensity` — мёртвый параметр.** Он есть в сигнатуре, но значения 1, 3 и 6
дают ровно **0.0 %** разницы и по темпу, и по тону. Не тратьте на него время.

Проверка делается байтовым сравнением: синтез Silero детерминирован (два
прогона дают одинаковый md5), поэтому «флаг не влияет» и «флаг влияет»
различаются надёжно.

### Ручные ударения — знак `+`

Алфавит модели содержит `+` — знак ставится **перед гласной** ударного слога:

```
хор+ошо        -> хорошО
замк+и         -> замкИ (механизмы)
з+амки         -> зАмки (двери)
```

Это единственный способ гарантировать ударение в имени или редком слове.
Автоматика ошибается — см. раздел про омографы ниже.

### Библиотека `silero-stress` — ударения и омографы

Отдельный пакет Silero (не часть TTS): умеет расставлять ударения, «ё» и
разрешать омографы по контексту.

```bash
uv pip install --python ~/models/tts-venv/bin/python silero-stress
```

```python
import silero_stress
acc = silero_stress.load_accentor()
acc.homosolver("Мука стоит дорого")   # -> "Мук+а ст+оит д+орого"
acc.accentor("текст")                 # только ударения, без омографов
```

Разбирает по контексту верно:
- «Мука стоит дорого» -> `Мук+а` (мукА, не мУка)
- «Я мою руки» -> `м+ою` (мОю, не мою)
- «Вечерний замок был красив» -> `з+амок` (строение)

**Ограничение:** контекст берётся в пределах предложения. «Все замки закрыты»
она разобрала как `замк+и` (механизмы), хотя по смыслу это `зАмки` (двери).
Если смысл критичен — ставьте `+` вручную или правьте текст так, чтобы
контекст был однозначным.

### Проверить всё без синтеза

```bash
python3 tools/voice_lab.py check -t "Напомни через 10 минут, открой YouTube в 19:45"
```

Покажет нормализованный текст, что модель вырезала бы без неё и как
разобрались ударения. Быстро — модель не загружается.

## 2. Темп: номинал ≠ факт (главная грабля)

`rate="105%"` **не** даёт ускорение на 5 %. Длительность квантуется кадрами
(шаг ~12.5 мс), поэтому зависимость ступенчатая. Замеры на плате:

| `rate` | длительность | фактическое изменение |
|---|---|---|
| 100 % | 4.025 с | — |
| 104 % | 4.013 с | −0.31 % |
| **105 %** | 4.000 с | **−0.62 %** ← просили −5 % |
| 106 % | 3.987 с | −0.93 % |
| **108 %** | 3.850 с | **−4.35 %** ← ближайшее к −5 % |
| 110 % | 3.763 с | −6.52 % |
| 115 % | 3.575 с | −11.18 % |
| 120 % | 3.425 с | −14.91 % |
| `slow` | 4.888 с | +21.43 % |
| `medium` | 4.025 с | 0 % (= 100 %) |
| `fast` | 3.425 с | −14.91 % (= 120 %) |

Между −4.35 % и −6.52 % **промежуточных ступеней нет**. Поэтому «ускорить
ровно на 5 %» физически недостижимо — можно только выбрать ближайшую.

**Эффект зависит от текста.** Мерить надо на той фразе, которая пойдёт в
ассистент, а не на тестовой:

```bash
python3 tools/voice_lab.py tune -t "Хорошо, включаю свет в гостиной." --target -5
# таблица «rate -> фактическое отклонение» + ближайшая ступень к цели
```

## 3. Интонация: почему вопрос звучит как утверждение

Это реальная ошибка, в которую легко попасть. Механика:

- Русский вопрос (ИК-3) — это **низкий старт** и **высокий хвост**:
  максимум F0 смещён к концу фразы.
- Утверждение — наоборот, пик в начале/середине, хвост падает.

Если обернуть **всю** фразу вопроса в `pitch="high"`, голос начинает уже
у верхней границы диапазона — восходящей дуге **некуда расти**. Замеры:

| Вариант | старт | пик | позиция пика | хвост/начало |
|---|---|---|---|---|
| вопрос «как надо» | 221 Гц | 349 Гц | — | восходящая дуга |
| вопрос **сломанный** | 287 Гц | 378 Гц | начало | ровно/вниз |

Старт 287 Гц против 221 Гц — и вопроса нет. Поэтому в профилях вопроса
высоким делается **только хвост** (последние 2 слова), а начало — низким.

Проверка одной командой, с вердиктом:

```bash
python3 tools/voice_lab.py question -t "Включить свет в спальне?"
```

Стенд сравнит пять вариантов (вся фраза высоким / низким / без тона /
высокий хвост / профиль warm) и по замерам скажет, где получился вопрос,
а где утверждение. Метрики: `peak_pos` (где стоит максимум F0 по времени) и
`tail_gain` (насколько хвост выше начала).

## 4. Что делать с цифрами и латиницей (потеря смысла!)

**Модель молча удаляет** всё, что вне её алфавита: цифры, латиницу, эмодзи,
знаки вроде `°`, `%`. Без предупреждения и без ошибки. Проверено обратным
распознаванием (TTS -> ASR):

| Писали | Слышно |
|---|---|
| «Включи свет через 10 минут.» | «Включи свет через **минуту**.» — смысл потерян |
| «Открой YouTube и Telegram.» | «Открой и» |
| «Сейчас 19:45.» | «Сейчас.» |

Обходные пути **не помогают**: `save_wav`, обёртка `<speak>`, `lang="ru"` —
результат одинаковый. Единственное решение — переписать текст словами
**до** синтеза. Это делает `tts_core.normalize_text()` (включена в `say.sh`
по умолчанию):

```
«Напомни через 10 минут, открой YouTube в 19:45.»
  -> «Напомни через десять минут, открой ютуб в девятнадцать сорок пять.»
```

Что нормализуется:

| Было | Стало |
|---|---|
| `19:45` | девятнадцать сорок пять |
| `19:05` | девятнадцать ноль пять |
| `через 1 минуту` | через одну минуту (род и падеж!) |
| `через 21 минуту` | через двадцать одну минуту |
| `-3°C` | минус три градуса |
| `скидка 50%` | скидка пятьдесят процентов |
| `YouTube` | ютуб (по словарю) |

**Почему не просто `num2words`:** библиотека всегда отдаёт мужской род и
именительный падеж, поэтому «1 минута» превращается в «один минута» — ошибка,
слышимая носителем. Нужна правка хвоста числительного под род и падеж
(`одна`/`одну`/`две`/`одно`), это делает `num2words`-обёртка в `tts_core.py`.

> **Безопасность зависимостей.** `num2words` **пинить на `0.5.14`**:
> версии 0.5.15 и 0.5.16 были опубликованы злоумышленником после фишинговой
> атаки и содержали вредоносный код (PYSEC-2025-72, GHSA-jxr6-qrxx-2ph2).
> Обе удалены с PyPI, но автоматические обновлятели всё ещё пытаются их
> поставить. В проекте зависимость объявлена с пином.

Проверка на любом тексте перед продакшеном:

```bash
python3 tools/voice_lab.py check -t "<ваш текст>"
# или
./scripts/say.sh --check "<ваш текст>"    # только показать риски, без синтеза
```

## 5. Профили интонации

Профиль — именованный рецепт SSML. Список и назначение:

| Профиль | Что делает |
|---|---|
| `neutral` | как есть, без настроек — точка отсчёта для сравнения |
| **`warm`** | **выбран: 1-я фраза ниже, дальше выше, пауза 350 мс, темп 108 %** |
| `lively` | бодро: темп 110 %, тон выше, фразы раздельно |
| `alert` | тревожно: первая фраза выше тоном, короткая пауза 250 мс |
| `calm` | спокойно: темп 90 %, тон ниже |
| `question` | вопрос: низкий старт + высокий хвост (ИК-3) |
| `emphasis` | акцент на первом слове за счёт темпа и паузы |

Почему `warm`: из палитры вариантов, прослушанных на реальных фразах
ассистента, выбраны `4-warm` и `5-lively`; после подбора темпа победил
`warm` с `rate="108%"`. При выборе из палитры предлагать сразу эти два.

```bash
# палитра всех рецептов на своём тексте
python3 tools/voice_lab.py palette -t "Добрый вечер! Чем могу помочь?"
# -> ./lab/baya-palette/*.ogg — слушать и выбирать номер
```

## 6. Практические сценарии

### Подобрать голос под задачу

```bash
# у ассистента есть реплики разного типа — проверяем на них
python3 tools/voice_lab.py compare \
  -t "Добрый вечер! Чем могу помочь?" --voices baya,kseniya,xenia
python3 tools/voice_lab.py compare \
  -t "Внимание! Датчик протечки сработал на кухне." --voices baya,kseniya,xenia
```

Слушать `./lab/compare/*.ogg`, выбирать по звучанию. Решение принимает
человек: метрики лишь показывают, что разница есть, но не какая «лучше».

### Добиться нужного ускорения

```bash
python3 tools/voice_lab.py tune -t "продакшен-фраза" --target -5
```

Читать **фактическое** отклонение, а не номинальный процент.

### Починить интонацию вопроса

```bash
python3 tools/voice_lab.py question -t "Включить свет в спальне?"
```

Если вердикт «УТВЕРЖДЕНИЕ» и старт выше ~265 Гц — уберите `pitch="high"`
с начала фразы, оставьте его только на хвосте (профиль `question`/`warm`
делает это сам).

### Проверить, не потеряется ли смысл

```bash
./scripts/say.sh --check "Напомни через 10 минут про 19:45"
```

### Озвучить с нужной интонацией

```bash
./scripts/say.sh -p alert "Внимание! Датчик протечки сработал."
./scripts/say.sh -p question "Включить свет в спальне?"
./scripts/say.sh -v xenia -s 1.1 -p lively "Готово!"
./scripts/say.sh -o /tmp/out.wav -p calm "Спокойной ночи."
```

## 7. Про «эмоции» — чего в Silero нет

Полезно знать заранее, чтобы не искать несуществующее.

**Silero не умеет эмоций** — ни радости, ни тревоги. Она умеет **интонацию**.
Доступны ровно три рычага:

1. **высота тона** (`pitch`) — делает голос выше/ниже; читается как
   «бодрее/спокойнее», но это тембр, а не эмоция;
2. **темп** (`rate`) — быстро/медленно;
3. **паузы** (`break`) — ритм, вес фраз.

У Алисы и Siri — те же три ручки. Для ассистента этого обычно достаточно.

Если нужна настоящая выразительность (смех, испуг, удивление) — это другая
модель. **GigaTTS у Сбера** умеет эмоции, но **открытых весов нет**, только
облачный SaluteSpeech API. Не путать с **GigaAM** — это ASR, он открыт и
уже используется в проекте.

## 8. Чего ещё ожидать

**Сбросы платы при синтезе.** Плата BPI-W3 уходит в аппаратный сброс из-за
просадки питания (пользователь меняет БП на внешний 12 В). Симптом: задача
обрывается, файлы не дописываются, `uptime` маленький. Это **железо, а не
софт** — не искать софтовую причину. Следствия для стенда:

- запускать короткими порциями;
- писать файлы сразу после каждого синтеза (стенд так и делает);
- в долгих прогонах делать скрипт идемпотентным (готовый файл = пропуск).

**Повреждение файлов.** Аппаратный сброс обрезает записываемые файлы —
наблюдались `METADATA` в venv, усечённые ровно до 0 байт. После серии
сбросов проверяйте целостность модели:

```bash
md5sum ~/models/tts/silero_v5_5_ru_ok.pt
# эталон: 3f9553af786a7c6da468d436276eebb4
```

**Задержка синтеза.** RTF 0.13–0.18 при `set_num_threads(2)`, то есть
в 5–7 раз быстрее реального времени; первый вызов ~1.5 с на загрузку модели.
Модель держите резидентной, не перезапускайте на каждую фразу.

## 9. Шпаргалка

```bash
python3 tools/voice_lab.py list          # что вообще можно менять
python3 tools/voice_lab.py check -t "…"  # ударения + цифры/латиница
python3 tools/voice_lab.py palette -t "…"     # палитра рецептов
python3 tools/voice_lab.py compare --voices baya,kseniya,xenia -t "…"
python3 tools/voice_lab.py tune --target -5 -t "…"
python3 tools/voice_lab.py question -t "…?"
python3 tools/voice_lab.py say -p warm -o ./out "…"
```

Правила, которые стоит помнить:

1. **Цифры и латиницу переписывать словами** — иначе модель их вырежет и
   смысл исказится.
2. **Проценты темпа мерить, не выставлять из головы** — номинал ≠ факт.
3. **`pitch="high"` на всю фразу убивает вопрос** — высота только на хвосте.
4. **Громкость выравнивать по RMS** перед сравнением голосов.
5. **`intensity` не работает**, `<emphasis>` не работает, `+` работает.
6. **Кастомные голоса недобавимы** — только 5 встроенных.
7. **`num2words` пинить на 0.5.14** — 0.5.15/0.5.16 были вредоносными.
