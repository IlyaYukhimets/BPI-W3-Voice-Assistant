# 14. Веб-панель ассистента

## Зачем

Проект вырос: три резидентные службы, слой KWS, модель ASR, папка сегментов,
журналы. Чтобы не ходить в ssh за каждой мелочью, панель показывает состояние в
одном месте — и то же, что видно в журнале, но наглядно.

Адрес: `http://<ip платы>:8080` (например `http://192.168.0.171:8080`).

## Компоновка

Раскладка нарочно НЕ авто-адаптивная. `repeat(auto-fit, minmax(...))` даёт дыры:
блоки разной высоты встают в общий ряд, и рядом с высоким блоком открывается
пустое место. Здесь фиксированная схема по смыслу:

* сверху на всю ширину — схема тракта (она горизонтальная, ей нужна ширина);
* слева колонка «что происходит»: график уровней, последние фразы, KWS;
* справа колонка «чем управлять»: службы (с кнопкой перезапуска в строке),
  действия, модели, файлы сегментов;
* снизу на всю ширину — журналы (три столбца) и документы (компактные чипсы).

Колонки — независимые flex-колонки, поэтому внутри каждой блоки стоят вплотную.
На узком экране (меньше 1000 px) колонки складываются в одну.

## Что показывает

* **Хост** — имя, адрес, uptime, доступная и общая память, температура,
  устройства захвата. Память важна: резидентные TTS и ASR занимают ~1.4 ГБ
  из 8.
* **Схема тракта** — микрофон → Vosk-KWS → сигнал → запись команды → GigaAM →
  голос → колонка, с живым состоянием каждой ступени. Устройство и формы имени
  берутся из `ExecStart` юнита, а не из кода, — панель показывает то, что
  реально запущено.
* **Службы** — `active/failed`, PID, RSS из `/proc` (systemd для user-юнитов
  память не отдаёт), число перезапусков.
* **Последние фразы** — номер, длина речи, пик (полоска уровня) и распознанный
  текст. Собирается по НОМЕРУ сегмента из строк `[seg] N: …` и `N: текст`,
  поэтому видно и неудачи: «не расслышал».
* **KWS** — сколько раз сработало имя, сколько кадров прослушано, громкость
  имени, а для пропущенной команды — запас: `шум 394, громче всего 765 против
  порога 709`. Именно по этому числу подбирается `--start-factor`.
* **Модели** — что на диске и сколько занимает.
* **Файлы сегментов** — что лежит в spool (имена с временем, размер).
* **Журналы в три столбца** — `voiced`, `asrd`, `ttsd` рядом, а не друг под
  другом: видно, что происходит одновременно. Служебный шум onnxruntime/Vosk и
  строки systemd отфильтрованы, события KWS и ответы подсвечены, ошибки красным.
* **График уровней** — пик каждой фразы по времени: зелёная точка — фраза
  распознана, жёлтая — нет. Сетка по уровню (−60…0 дБ) показывает шкалу. Сразу
  видно, при каком уровне микрофона распознавание начинает ломаться (на живой
  эксплуатации видно перелом около −20 дБ).
* **Документы во всплывающем окне** — по клику открывается сама документация
  (своя мини-разметка: заголовки, списки, код, таблицы, ссылки), без перехода на
  GitHub. Закрывается по Esc или клику мимо.
* **Действия (нужен ключ)** — два сигнала (при имени и после тишины) со своими
  кнопками прослушивания и применения, поле для фразы (две строки, Enter — сказать,
  Shift+Enter — перенос), кнопка **«сказать имя»**, которая выводит на колонку имя
  ассистента, список сигналов с подписями и прогон ASR по последнему записанному
  сегменту. Сигналов два, и в блоке две строки: **«при имени»** (открывающий) и **«после
тишины»** (закрывающий — когда имя услышано, а команды не вышло; в его списке есть
пункт «— тишина —»). В списках рядом со встроенными отбивками видны свои файлы из
`~/.assistant/cues` (пункт «файл · имя»); проверка при прослушивании идёт с той же
обрезкой, что и в цикле. Со сигналом две кнопки: **«прослушать»** играет вариант в колонке,
  **«сделать рабочим»** прописывает его в юнит (бэкап `voiced.service.bak`) и
  перезапускает цикл — дальше этим звуком идут все сигналы. Список заполняется
  один раз и выбор пользователя не сбрасывается обновлением состояния. Кнопка имени — это
  сквозная проверка тракта: ассистент услышит себя через микрофон, сработает KWS и
  прозвучит сигнал. Перезапуск служб переехал в таблицу служб — там ему и место.

## Ключ и действия

По умолчанию панель только читает. Действия включаются файлом с ключом:

    head -c 24 /dev/urandom | base64 > ~/.assistant/panel.token
    chmod 600 ~/.assistant/panel.token
    systemctl --user restart panel

Ключ вводится в панели в поле «ключ» (хранится в localStorage браузера) и
уходит в заголовке `X-Panel-Token`. Что защищено:

* без файла с ключом ручки отвечают `403` и кнопки неактивны — сама возможность
  что-то менять выключена на плате, а не в интерфейсе;
* сверка ключа идёт по байтам (`secrets.compare_digest`), поэтому не-ASCII
  ключи не роняют панель (тест `test_panel_parse` это ловит);
* службы для перезапуска — только `ttsd`, `asrd`, `voiced`, `panel`: чужое имя
  отвергается;
* текст для озвучки уходит аргументом без shell, длина ограничена — командой он
  стать не может.

Кнопка «ASR по последнему» прогоняет распознавание тем же путём, что и рабочий
цикл (`voiced.recognize_segment`), и показывает текст с временем: удобно
проверить, что именно услышал ассистент, не произнося фразу заново.

## Почему без зависимостей и без изменений

Только стандартная библиотека (`http.server`) и системные команды, которые на
плате уже есть: `systemctl`, `journalctl`, `arecord`. Ни БД, ни шаблонизатора, ни
сборки. Панель **ничего не меняет** — она читает состояние служб, журнал
пользователя, свой spool и файлы моделей. Поэтому авторизации нет: защищать
нечего, кроме самой доступности, и та ограничена локальной сетью.

Если панель понадобится наружу — это отдельный шаг: проброс через Traefik так
же, как у остальных сервисов дома, плюс токен на чтение.

## API

`GET /api/state` возвращает весь срез одним JSON: `host`, `units`, `pipeline`,
`segments`, `kws`, `replies`, `spool`, `models`, `logs`, `docs`. Кэш 2 секунды,
чтобы автообновление страницы каждые 3 с не дёргало `journalctl` без нужды.

Этим API можно пользоваться и из скриптов: например, проверять, что все ступени
схемы в состоянии `ok`, или собирать статистику фраз.

## Запуск

    systemctl --user enable --now panel        # юнит systemd/panel.service
    journalctl --user -u panel                 # на случай, если не поднялась

Порт и адрес: `--port 8080`, `--bind 0.0.0.0` (вся локальная сеть).

## Как расширять

* новая ступень тракта — добавить элемент в `pipeline()`;
* правку юнита можно проверить тестом: `set_cue_option` принимает путь к юниту и
  запускатель команд (по умолчанию — настоящие), поэтому тест правит временный файл
  с подставным запускателем и не трогает живую службу;
* имена действий сервера объявлены одной константой `ACTIONS`, и обработчик
  сверяется с ней до работы веток; тест `test_panel_actions` сравнивает её с
  кнопками на странице в обе стороны — так ловится ошибка «кнопка зовёт сервер
  именем, которого он не знает» (она случалась дважды: `say_name`, `tone_close`);
* настройки для схемы читаются из `ExecStart` юнита: в юнитах команда разбита
  переносами через `\`, и склеивает их `exec_from_cat()` (иначе видны умолчания,
  а не то, что реально запущено);
* новый показатель — вернуть его в `state()` и отрисовать в JS;
* разбор журнала — регулярки `SEG_RE`, `TEXT_RE`, `FAIL_RE`, `KWS_RE`,
  `SILENT_RE`; всё разбирается чистыми функциями, они покрыты тестами
  (`test_panel_parse`), поэтому новый формат строк ловится сразу.

## Ограничения первой версии

* действия выключены, пока нет файла с ключом (осознанно: сначала посмотреть);
* правка юнита всегда с бэкапом: юнит запускает резидентную службу, и опечатка
  оставила бы ассистента без звука и без объяснений;
* журнал показывается в тех пределах, что отдаёт `journalctl` — история в файл
  не пишется;
* график уровней живёт в памяти панели: после её перезапуска история начинается
  заново;
* данные обновляются раз в 3 секунды, это не потоковый график.
